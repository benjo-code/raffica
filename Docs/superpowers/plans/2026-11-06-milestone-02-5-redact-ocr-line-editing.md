# Milestone 2.5 – Redact, OCR and line editing: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Raffica PDF removes content for real (redaction by selection, area and pattern, with the checked full rewrite), makes scans searchable (OCR with language management), and corrects existing text lines, and the OCR library is built in this repository instead of being fetched from Pagewing's prerelease.

**Architecture:** Core already holds everything below the UI and the command line uses it: `RedactionPlan`/`RedactionHistory`/`RedactionSearch`/`RedactionPatterns`/`RedactionExecutor.AnalyzeAsync` (the `RedactionAnalysis`)/`RedactionApplier.ApplyAsync` (working copy, rebuild into a page-less document, checked atomic rewrite, adoption, `RedactionCheck`); `OcrRunner.RunAsync`, `OcrLanguages`, `TessdataStore`, `PdfDocument.GetOcrPageInfoAsync`, `AnnotationEditor.ApplyOcrAsync` (one history step); `PdfDocument.GetTextRunsAsync`, `GetFontCoverageAsync`, `TextEditCheck.Evaluate`, `AnnotationEditor.ApplyTextEditAsync`. 2.5 adds the app side and the library build. Redaction is a pending plan with a full rewrite and follows the shape of 2.4 (session per tab, locks, Apply card, `JobRunner`, `PdfWindow.RebuildTab`, close guard). OCR and text editing write into the annotation editor's history and save incrementally through the existing `SaveController`, like marks. Logic without a window is plain classes tested without Avalonia; controls are tested headless as in 2.1 to 2.4.

**Tech Stack:** .NET 10 Native AOT, Avalonia 12.1.4, xunit.v3 3.2.2 with `Avalonia.Headless.XUnit` (`tests/Raffica.Pdf.Tests`), Core only for PDF work; GitHub Actions; no new package.

**Spec:** [Docs/superpowers/specs/2026-11-04-raffica-pdf-design.md](../specs/2026-11-04-raffica-pdf-design.md): sections 2 to 6 (saving, "Redaction removes content for real and ends with a full rewrite; the checks on extracted text and raw bytes stay", "Text editing is limited by design"), 7 (row 2.5), 8, 9. Frame rules: "App frame conventions (M1.2)", "viewer conventions (M2.1)", "annotation conventions (M2.2)", "forms and signing conventions (M2.3)", "page organizing conventions (M2.4)" in [Docs/DECISIONS.md](../../DECISIONS.md). Behaviour rules come from the predecessor's specs `2026-11-01-m14-schwaerzen-design.md`, `2026-11-01-m14-1-schwaerzen-muster-fuellungen-design.md`, `2026-11-02-teilprojekt4-ocr-design.md`, `2026-11-02-m16-text-bearbeiten-design.md` (read-only checkout `C:\VS-Code\Pagewing`, tag `v1.0.0`, read with `git show`; German); the rules a task uses are cited in English in that task. ## Global Constraints

- **Stack and layering:** `Raffica.Pdf` references `Raffica.Core` and `Raffica.Shell` only and knows no PDFium type. Every Core call is awaited, the UI thread never waits for PDFium or Tesseract. `RedactionApplier.ApplyAsync` runs on a pool thread, never from a `Changed` handler. Progress and `ViewerSession` events arrive on other threads: marshal to the UI thread before touching a control or `PdfTab`.
- **Never damage the original (spec 2):** redaction is Core's checked, atomic full rewrite; the app never writes a PDF itself. Any failure before the target is replaced leaves the target byte for byte as it was and the plan open. No backup copy (a silent write). OCR and text edits are unsaved history steps until the incremental save.
- **Say it before, never claim more than was checked (predecessor's decisions):** the Apply card lists what is removed, what the cleanup removes, what the rebuild loses and what is not cleaned; the result card lists what was checked and what was not (`RedactionCheck.NotChecked`). No UI text says "safe", "sicher", "guaranteed", "all found", "error-free", "complete", and no text calls a signature "valid" or anything "legally binding". The guard test `NoUiTextCallsAnythingLegallyBinding` is extended with the new texts in both languages, and a new guard `NoUiTextOverpromisesRemoval` covers the redaction, OCR and edit texts.
- **Sanitizing is not a switch (owner, 2026-11-06, kept from Core):** every Apply removes the cleanup list (`CleanupKind`: information dictionary fields, XMP, bookmarks, attachments, JavaScript, page labels); there is no toggle. Values of information fields are never shown, only the field name.
- **Look:** direction D, PDF ink plum, shell tokens and controls only, no hex literal in a component style (`NoHexInComponentStylesTests`). A mark, a locked run or a pending state is never shown by colour alone (hatching or icon plus text, with an automation name that never contains the marked text). A new colour token is not planned; if one becomes necessary the checklist in `CLAUDE.md` section "Shell" applies. Stand-in icons as in the other tabs.
- **Strings:** every UI string in `Strings.en.resx` and `Strings.de.resx` of the app project with an accessor in `PdfStrings`; `TranslationTests` and `CommandCatalogTests` stay green. Every Core enum that reaches the user (`RedactionRefusalKind`, `RedactionFallbackKind`, `RedactionLossKind`, `CleanupKind`, `RedactionNotCheckedKind`, `RedactionFindingKind`, `OcrSkipReason`, `TextEditLockReason`, `TextEditRejection`) has wording in both languages and a guard test that fails when a member has none (as `PageLossWordingTests`). The cards speak from these tables, never from Core's English sentences.
- **Startup (spec 5):** nothing of 2.5 is created before the user uses it: no `RedactSession`, no `OcrSession`, no text-run read, no tessdata scan, no library load, no probe at start or at the first sharp page, except the scan hint probe of Task 9 which runs after the first sharp page and only when the library is present (test `StartupCreatesNoRedactOcrOrEditWork`). `--measure-*` runs stay unchanged; the speed budgets are not touched.
- **Hostile input:** the Core limits apply and are tested through the UI path: `RedactionLimits.MaxMarks` (10 000), `MaxAreasPerMark` (500), `MaxTermLength` (1 000), `MaxOverlayTextLength` (200), `MaxRasterPixels` (32 000 000), `RedactionSearch.MaxHits`, `OcrLanguages.MaxLanguages` (8), `TessdataStore.MaxFileLength` (200 MB), `TextEditLimits` (2 000 characters per run, 5 000 runs per page). Every refusal ends in a card or note with its reason and no change.
- **Not in this milestone:** OSD or deskew, handwriting or layout analysis, downloading language data, `/Redact` annotations as saved markers, QPDF post-processing, find-and-replace, paragraph editing, a user-chosen replacement font, installers and the updater (2.6), macOS. Hardware measure: `measure.yml` already is the hardware-measure workflow, it is not added a second time.
- **Done** means: `dotnet build Raffica.slnx -c Release` (0 warnings), `RAFFICA_REQUIRE_OCR=1 dotnet test Raffica.slnx -c Release --no-build --max-parallel-test-modules 1`, `dotnet format Raffica.slnx --verify-no-changes` and `dotnet run tools/roadmap.cs -- check` green, each acceptance criterion with its proof in `Docs/roadmap.json`. Local builds may need `-p:NuGetAudit=false` (known advisory, see the 2.1 evidence).
- **Commits:** Conventional Commits with the trailer `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`; stage files by name; `git show --stat HEAD` after each commit; noreply address only. Branch `feature/m25-redact-ocr-line-editing`; PR to `dev` at the end (Task 2 may go as its own earlier PR, see there), merged when `ci` and `roadmap` are green. Tick roadmap tasks as they finish (`dotnet run tools/roadmap.cs -- generate`). Tests that write work on temp copies of the fixtures, never on `testdata`, never to the real user folder (tessdata and signatures lie next to `--settings-file`).
- **Owner gates (CLAUDE.md "Collaboration"):** running the native build workflow creates a prerelease in this repository, an external effect: ask the owner before `gh workflow run`. Nothing else in this plan touches GitHub settings, tags or releases.

## Calls made while planning (author's calls, the owner can overturn them)

1. **Redaction is mark, review, apply (predecessor's decision, kept).** Marks are a pending plan in the tab (`RedactSession` over Core's `RedactionHistory`); the page view keeps showing the unchanged document, marks are drawn by an overlay (hatched tint plus edge, never printed, never a PDF annotation). Nothing is written until Apply.
2. **Locks.** While a redaction plan is open: annotate tools, Sign, form clicks, the organize mode, OCR, text edit and the output commands (Extract, Split, Export images) are disabled with the visible reason "Apply or discard the redactions first"; Print stays. Entering the mode needs no open organize plan, no running OCR and no text-edit draft. One class (`ModeExclusion`, Task 3) holds the matrix and the reasons for all five modes, so no mode knows the others.
3. **A Redact ribbon tab (letter R) and an Edit tab (letter E).** Redact: groups Mark, Find, Look, Apply and, set apart last, the destructive group (Delete marks, Discard all). Edit: groups Text (Edit text) and Scan (Recognize text…, Language files…). If `RibbonDefinitionTests` finds a clash, use `X` for Redact and `T` for Edit. No new window-level key capture; the only shortcuts are Ctrl+Shift+P (Redact mode) and Ctrl+Shift+Q (Recognize text…), as in the predecessor, plus Ctrl+Shift+W (Edit text); Ctrl+Enter marks the text selection while the mode is on.
4. **The redact pane replaces the marks pane in the right pane slot while the mode is on** (256 px, field code 7): mark list grouped by page, the Find panel (term, match case, whole words, "Patterns" mode with four kinds) and the appearance rows (fill, image treatment and strength, overlay text). No second pane.
5. **Appearance is per plan, overlay text per mark** (Core's model): fill colour (black default, white, five presets, `#RRGGBB`), image treatment Solid (default), Pixelate, Blur with Coarse or VeryCoarse, overlay text with Repeat and AutoSize. The mandatory caution (text in images may stay readable, choose solid) is shown whenever Pixelate or Blur is chosen, on the Apply card and in the result.
6. **Rescue by turning pages into images is explicit.** A page refused as `PageNotRedactable` is listed on the Apply card with its numbers (`RasterPageInfo`: dpi, pixels, "up to N MB", annotations, links, form fields, text) and a tick per page; Apply stays blocked while a refused page is neither ticked nor removed from the plan. Any page can also be marked "as image" freely (Look group). `Encrypted` and `UnremovablePageKeys` offer nothing.
7. **Scanned pages are sent to OCR (new, not in the predecessor).** When a search or pattern run finds nothing on pages that have no text layer (`GetOcrPageInfoAsync`: fewer than `OcrPlanner.TextThreshold` characters and an image over 80 percent of the page), the Find panel says "N pages are pictures; text in pictures is not searched" with the command "Recognize text…" next to it. It never starts OCR by itself.
8. **Apply defaults to "Save as…" (suggested name `<name>-redacted.pdf`); "Save in the original file" is armed (locked 400 ms, never the default), also when the picked path is the original's.** Success adopts the written file, rebuilds the tab (`PdfWindow.RebuildTab`) and opens the result card with sections Removed, Cleaned, Checked (only when clean) and Not checked. A finding writes nothing and names the kind and page, never the text.
9. **OCR options are a card, the run is not.** The Recognize card (languages as checkboxes, pages: all without text, all, current, range; mode Skip/Redo/Force worded as in the predecessor; resolution Automatic, 150, 200, 300, 400) starts the run and closes. The run shows in a run badge in the page view's `BadgeHost` slot and in the status bar hint ("3 of 12 pages"), with Cancel; the document stays readable and scrollable. Cancel with finished pages asks "Keep finished pages / Discard" (Discard default). A finished run is applied at once as one unsaved history step (`ApplyOcrAsync`), then the report card opens. Cheap to change: only Task 9 decides.
10. **Language data (owner decisions kept):** English and German `tessdata_fast` are bundled next to the app; more come from the user folder by "Language files…" (copy, trust warning before the file picker, never a download); an imported file of the same name beats the bundled one (that is how `tessdata_best` can be dropped in); the last choice is stored in `AppSettings.OcrLanguages`. The import runs off the UI thread (the predecessor's known gap).
11. **Text editing is a mode of the page view.** Run outlines (dashed with a lock icon and a reason for locked runs), an inline single-line field over the run, a hint bar ("Edit lines, not paragraphs. Characters the font lacks are set in a replacement font."), live notes for missing characters, rejection, overlap and page edge, and the switch "Whole line in replacement font" (never preselected, offered only when `WholeRunInGeistPossible`). An empty text removes the run with the note "Empty: the line is taken away. Undo brings it back." Enter commits, Esc discards, Tab commits and leaves (never traps focus). An open draft counts as an unresolved edit (`AnnotationSession.BeginUnresolved`) and is flushed before save, print, mode end, close.
12. **Old text stays in earlier revisions of an incrementally saved file.** After the first save of edited text the status bar says so once per tab ("The old text stays in earlier versions of the file. To remove it for real: Redact."); no forced rewrite (owner decision of the predecessor).
13. **OCR library build (spec 2.5 first task).** A dispatch-only workflow on hosted runners (it compiles third-party source) builds Tesseract 5.5.4 and Leptonica 1.87.0 from pinned commits with the flags of the predecessor's build (no OpenMP, curl or archive support, static CRT on Windows, static libstdc++ on Linux) and publishes `tesseract.dll` and `libtesseract.so` to a prerelease `native-tesseract-5.5.4-1` of this repository (the tag never starts with `v`, so no update check reads it). The repository is private, so `tools/native-fetch.cs` reads the release assets through the GitHub API with a token (`GITHUB_TOKEN` in CI, `GH_TOKEN` locally) and works unauthenticated once the repository is public; the pinned size and SHA-256 per file stay the trust anchor.
14. **CodeQL returns, guarded** (`if: github.event.repository.private == false`, as the predecessor had it: it runs once the repository is public). The hardware-measure workflow is `measure.yml`, which exists.

## Review Focus

1. **A term hidden in places the page text does not show** (white text, tiny text, annotation, form field, an old revision, metadata, an attachment): Expected: the removal test passes through the UI path for `redact-attachments`, `redact-revisions`, `redact-covered`, `redact-fonts` (with an extra area mark for the line a text search misses), `redact-hidden` and `redact-everywhere` (both need the page-as-image rescue) (extracted text and raw bytes). `redact-structure` and `redact-objstm` are refused by Core for unremovable page keys and the acceptance asserts the refusal (corrected during Task 7). Pinned by `RedactUiAcceptanceTests.EveryFixtureLeavesNoTermInTextOrBytes` (Task 7).
2. **Apply while something else holds the document** (a running save, a running OCR, an open draft, a changed original, an encrypted or signed file): Expected: the card refuses or asks, the file is byte for byte as it was, the plan stays. Pinned by `RedactApplyFailureTests.EveryFailureKeepsTheFileAndThePlan` (Task 7).
3. **Closing or leaving with pending marks, a running OCR or an open text draft**: Expected: the generic question for the kind, nothing lost silently, a running OCR is canceled by closing. Pinned by `RedactCloseTests`, `OcrCloseTests`, `TextEditDraftTests.CloseAsksAndFlushes` (Tasks 7, 9, 10).
4. **Scanned or image-only pages**: Expected: pattern search names the pages it could not search and offers OCR; an OCR on a signed or encrypted file warns or refuses; a page of a scan with `Pixelate` still shows the caution. Pinned by `RedactFindTests.PicturePagesAreNamedWithTheOcrOffer`, `OcrSignedFileTests`, `RedactAppearanceTests.CautionShownForBlurAndPixelate` (Tasks 5, 6, 9).
5. **Locked and odd runs in text edit** (OCR layer, Type 3, vertical, ligature, a character neither font has, a 2 001-character run): Expected: the reason is shown beside the run, nothing changes, no silent drop. Pinned by `TextEditLockWordingTests` and `TextEditRejectTests` (Task 10).
