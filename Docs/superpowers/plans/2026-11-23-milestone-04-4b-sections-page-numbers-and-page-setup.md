# Raffica Write 4.4b: Sections, Page Numbers, Headers and Footers, Page Setup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A writer can start page numbering at any page ("1", "i", "A-1") with one command, see and remove the section it made, set headers and footers per section (own or same as previous, first page, left and right pages), insert a page number, and change size, margins, orientation and columns for a section, the whole document or from here on, and no page number is ever wrong.

**Architecture:** Sections are a read-only view (`SectionList`) over the body's `Paragraph.SectionBreak` and `Story.FinalSection`; page setup is typed accessors over `SectionProperties`. Every section command is one history step: block changes (the paragraph that carries a new break) plus a `SectionChange` that swaps the content of `SectionProperties` objects in place and the document's left-and-right-pages flag; new header and footer parts and the `PAGE` field are built by new UI-free helpers in `Raffica.Write.Editing` and are never removed. A command that touches sections restarts the layout through `DocumentLayout.Resection` (the `Restyle` path, no new fast path). The app adds a Layout tab, two cards, a Sections pane in the formatting pane's slot, and a marker overlay drawn by the page view.

**Tech Stack:** .NET 10 Native AOT, Avalonia 12, Open XML SDK 3.x (package layer only), xunit v3 on Microsoft Testing Platform.

**Spec:** `Docs/superpowers/specs/2026-11-23-raffica-write-4-4b-sections-page-numbers-and-page-setup-design.md` (approved 2026-11-23, with "Settled after the builder check"). Subproject spec: `Docs/superpowers/specs/2026-11-13-raffica-write-design.md` (section 6 "Structure"). Branch: `feature/m44b-sections-and-page-setup`. Read the sections "Write library (M4.1)", "Write editing (M4.3a)", "Write formatting (M4.3b)", "Write recovery (M4.3c)" and "Write structure (M4.4a)" of `CLAUDE.md` first: the rules there (lease, attribution, oracle, start cost, Home band width hint, CRLF) bind every task.

## Global Constraints

- .NET 10 Native AOT, English source, German localization in the "Sie" form; every new command has its own Lucide icon, a reason in every disabled state (`WriteCommandRules`), strings in both `.resx` files (LF), and a line in `WriteMacMenu`; no warning suppressed; `dotnet format Raffica.slnx --verify-no-changes` clean. The Write tool makes CRLF files: convert to LF before each commit.
- **The model is the vocabulary:** sections go through `SectionProperties`, `Paragraph.SectionBreak`, `Story.FinalSection`, `HeaderFooterReference`, `HeaderFooterPart`, `WordDocument.HeadersFooters` and `DocumentSettings.EvenAndOddHeaders`; the section list is a view, not a second storage; children are placed by `SchemaOrder`; unknown children stay.
- **Number pages from here:** next-page break before the top-level body block that holds the caret (carried by the previous plain paragraph, else a new empty paragraph); no split when the caret is in the first block of the document or of a section; never an empty or redundant section; a new section made by a split has no `w:titlePg`; `w:pgNumType` with `w:start` (omitted for "continue") and `w:fmt`; footers are written per used type (default; first only if `titlePg` stays on; even only if the document has left and right pages): nothing for a type that already resolves to a footer with a `PAGE` field, else the section's own footer of that type with the number centered; with a prefix, an own footer of each type (a copy with the prefix before `PAGE`); the earlier half keeps what it had. A caret in a header, footer, note or comment, or a prefix document, disables it with a reason.
- **"From here" reaches the end of the document:** later sections that do not set their own value inherit it; a later section with its own footer, `w:pgNumType`, size, orientation or columns keeps it; the card names how many sections follow. Page setup "from here on" splits the same way (next page; continuous for columns) and sets only the changed property in the new and every later section, as one step.
- **Marker removal merges into the previous section:** the paragraph that carried the break of section k-1 loses its `w:sectPr`; the end properties of section k keep their object and take the whole content (attributes, every child, unknown ones, references, `w:type`, `w:pgNumType`, `w:titlePg`) of the former properties of section k-1 as a clone; same rule for a middle and the final section; one undo step.
- **Headers and footers:** "own" creates a part (new relationship id, `w:hdr` or `w:ftr` root, a copy of the inherited content) and a reference; "same as previous" removes the reference (the part stays unused); the first section is always own. Different first page sets or clears `w:titlePg` and creates an empty own first header and footer only where none resolves. Left and right pages is `evenAndOddHeaders` (document-wide, created if missing); turning it on gives each section with its own default part an even copy, inheriting sections inherit; turning it off leaves the parts. Editing shared content edits it for every section that shares it, and the status line says so. No part or numbering definition is ever removed.
- **Insert page number:** a picker of looks (`1`, `Page 1`, `Page 1 of N`, `1 / N`, words in the UI language at insertion) and places (header or footer; left, centre, right); writes into the story the caret's section uses (the caret's own header or footer at the caret); replaces a paragraph that already holds a `PAGE` field in that place; a complex field (`fldChar` begin, `instrText`, separate, result, end), `NUMPAGES` likewise, cached result the number of the caret's page; a field stays one unit. `NUMPAGES` is the physical total; the picker hints "N counts every page" when the numbers are not 1 to N.
- **Page setup:** typed access to `w:pgSz` (and `w:orient`, which Write must write), `w:pgMar`, `w:cols`; size A4, Letter, A3, A5, Legal and custom; margins Normal, Narrow, Moderate, Wide and exact values, cm or inch by region as `BlankPaper.For`; orientation swaps width and height; columns one, two, three, exact count, spacing, line between; "Apply to" this section, whole document or from here on, default whole document when there is one section, else this section; header and footer distances and the gutter are never touched.
- Plain section breaks: next page, continuous, even page, odd page (`w:type`), same split rule.
- The outline moves a chapter that holds a section break; a move is refused with a reason when it would leave a section-break paragraph as the last body block. The editor keeps refusing to delete or merge a section-break paragraph and now shows a reason that points to the marker.
- Every model change goes through the lease and `EditSession.Apply`, one history step per command, every raise followed by `DocumentEdits.Attribute`; the final `w:sectPr` and the settings part must reach `BodySnapshotCache` output and the recovery copy (a case in `SnapshotCacheOracleTests`, byte equality with the user-save writer). Incremental equals full: `LayoutOracle.AssertEqualToFull`, exact equality.
- Start cost: nothing of sections, the Layout tab pickers, the pane, the marker overlay or the page-number builder exists before first use (`StartupCreatesNoSectionWork`); a new tab must not change the Home band's width hint (`RibbonStartupTests`); measure `--measure-startup` against the commit before 4.4b. Typing stays at most 16.0 ms with the Sections pane open; `typing`, `format` and `structure` limits are not loosened. Reads are lazy, bounded and memoized by model, revision and selection; beyond 200 sections the pane says "too many to list".
- A prefix document refuses every section command. The marker overlay is never part of a `LaidOutPage` and never reaches print or PDF export.
- Out of scope: page borders, line numbers, vertical alignment, watermarks, a header gallery, gutter and mirrored margins, text direction, per-section footnote settings, `SECTIONPAGES` looks, fields beyond `PAGE` and `NUMPAGES`, an Insert tab (4.5), shortcuts for the new commands, the owner gates of earlier milestones.

## Review Focus

1. A blank document of three pages, caret at the top of page 3: number from here gives "1" on page 3 and no number on pages 1 and 2; the same on a document that already has numbers in every section and on one with no footers at all (Task 5, `PageThreeShowsOneOnABlankDocument`, `ARestartOnADocumentThatAlreadyNumbersOnlyRestartsTheCount`).
2. A Word-made document with later sections that have their own footers or `pgNumType`, with `titlePg` set and an empty first-page footer, and with left and right pages on: the numbered section shows the number on its first page and its even pages, later own settings stay (Task 5, `TheFirstPageOfTheNewSectionShowsTheNumber`, `LaterSectionsWithTheirOwnSettingsKeepThem`, `EvenPagesShowTheNumberWhenLeftAndRightPagesAreOn`).
3. Marker removal on the final section, on a middle section whose setups differ, then undo, redo, save and reopen: the properties come back exactly and the unused parts stay harmless (Tasks 5 and 9, `RemovingAMiddleSectionTakesThePreviousSetupWholesale`, `UndoOfARemovalRestoresTheParts`).
4. The caret in a header, footer, note, table, block content control, the first block, a prefix document, a document with 1,000 sections, and a section-break paragraph as the last block: disabled with a reason or a deterministic place, never an exception, never an empty section (Tasks 5, 10, 11).
5. Page setup on a document with several sections for each scope, orientation twice, a section without `w:pgSz`, and a continuous section after a size change: the page count and numbers equal a full layout and the reference (Tasks 8 and 9).

### Task 8: Page setup

**Files:** Create `TextEditor.PageSetup.cs`. Test: `tests/Raffica.Write.Tests/Editing/PageSetupEditingTests.cs`.
